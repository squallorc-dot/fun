## 架構與實際測試

`signaling/worker/worker.mjs` 以 SQLite-backed Durable Object、hibernation WebSocket、房間過期 alarm 實作兩人訊號原型。房間識別碼不是憑證，兩個 256 位隨機憑證透過 WebSocket 首次訊息驗證，憑證雜湊存在房間儲存；訊號伺服器只轉送 offer／answer。`arcade/assets/friend-signaling.js` 沿用 `BioPeer.Link`，其現有做法是等待 ICE gathering 完成，將 candidates 內含於 SDP 一次交換，並非 trickle ICE；遊戲資料仍走原有 DataChannel，不使用 STUN／TURN。訊號模組尚未接入正式 UI。

- 本機 `wrangler dev --local` 使用 Workerd；`scripts/test-signaling-v161.mjs` 通過來源拒絕、建立房間、錯誤憑證拒絕、相同角色重複加入拒絕、雙方 WebSocket 訊號交換及房主離開清理。測試只輸出狀態，未記錄信號或憑證。
- 同腳本 `--rtc` 以兩個獨立 Chromium 程序測試自動配對，**未通過**：此 Cloud 執行環境本機 Chromium 產生 0 個 ICE candidates，結果為 `pairing-failed`／`peer-left`。沒有更改安全政策。GitHub Actions [41053292689](https://github.com/squallorc-dot/fun/actions/runs/41053292689) 對提交 `ab1aea7` 已用本機 Worker 及兩個獨立 Chromium 程序成功建立真正 DataChannel 並雙向傳輸；後續修改須以最新提交的結果為準。
- hibernation 在程式中使用 `acceptWebSocket` 與 attachment，但本機測試尚未證明真實 Cloudflare 休眠與喚醒。免費用量、雲端部署和網路条件均未驗收。

## 跨房間速率限制與本機測試

- Worker 現有新增獨立 SQLite `RateGate`；各 Cloudflare 來源位址分別限制每 60 秒建立房間 12 次、WebSocket 升級 60 次，與房間內既有上限共同使用。缺少 `RATE_SECRET`、來源標頭或速率物件時回傳 503，達上限回傳 429。共用 NAT 的人會共享配額；這些是候選門檻，尚待真實使用資料調整。
- 只將來源位址以 `RATE_SECRET` 做 HMAC 後作為物件識別，不儲存原始 IP；資料在時間窗結束後由 alarm 清理。前提是公開流量真正由 Cloudflare 注入可信的 `CF-Connecting-IP`，不得把使用者自填的標頭當成正式來源。此限制不是分散式攻擊或成本控制的完整解法。
- `scripts/test-signaling-rate-v161.mjs` 測試並行上限、時間窗恢復、錯誤設定預設拒絕及 HMAC 隔離；`scripts/test-signaling-live-rate-v161.mjs` 在本機 Workerd 以文件保留位址模擬來源，實測跨房間 12 次成功與超限、另一來源隔離。測試代理注入的位址只是本機測試，不是 Cloudflare ingress 驗證。
- 實際部署前須以 Cloudflare 安全機制設定具高熵的 `RATE_SECRET`（例如在已授權的終端由 `openssl rand -hex 32` 管線傳給 `wrangler secret put RATE_SECRET`），不要將值寫入 Git、輸出、對話或前端。CI 所用字串僅為公開的本機測試常數，不能用於雲端。新 binding 和 migration 的雲端可用性及實際成本尚未核實。
- 未核准的房間碼請求斷線時會通知房主清除待確認畫面；Node 單元及本機 Workerd 真正 WebSocket 測試覆蓋此清理與核准，真實裝置及長時間網路情況尚待驗證。

## 安全重連候選實作

- 房間對意外信號中斷提供最多 90 秒恢復期限，每角色最多兩次；恢復憑證以雜湊儲存、每次使用後輪替，並拒絕活躍角色取代與舊憑證重放。房主主動離開或恢復期限／次數耗盡時關閉房間。
- RTC 中斷時原局清理，不恢復比分或進度；雙方在同房間各自確認重新連線，房主權威協調新 RTC，返回大廳並重新準備。每房間最多兩次重新配對；信號不可用或過期時安全失敗。
- 單元及本機 Workerd 測試檢查信號恢復、重放拒絕、雙方同意、重試上限、過期、主動離開；真正雙 Chromium RTC 重連、全套 CI 及真機仍須以最新執行結果為準。詳細手動驗收見 `signaling/真人驗收表.md`。
