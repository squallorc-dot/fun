> 所有項目是**發布前尚待確認的 Gate**。除已具測試紀錄者外，不應聲稱已完成。請由主對話框執行並提交可追溯的 CI／瀏覽器／真機證據。

## A. 實際發布定義：一次發六款，而非六款都在同一程式碼檔案

正式發布應讓使用者從既有網站首頁／互動體驗入口，無障礙地進入中日文 Arcade 大廳，看到六款主遊戲 G01–G06 且全部可按開始、完成一局、敗北／勝利、結果、重試、退出；G05 另含排球、桌球兩套模式。OST 有播放器與存檔，原有問卷不消失。發包期間全部整合工作仍在 `development/bio-city-arcade-six-games` 進行，可以製作受控 QA preview，但正式 `main` 的遊戲入口不得提前公開。

## C. Gate 1：程式與自動化測試（BLOCKER）

在**完整 repo checkout** 執行：

```bash
node --check arcade/assets/hub.js
node --check arcade/assets/games-core.js
node --check assets/arcade-engine.js
node scripts/test-arcade-engines.cjs
node scripts/verify-arcade.mjs
node scripts/build.mjs --check
node scripts/verify.mjs
```

- [ ] 全部指令 Exit Code = 0；不能只跑 `node --check` 略過遊戲回合。
- [ ] 特別修復 **G05 無介面測試在 9000 frame 未結算** 的已知問題，排球／桌球皆須分開測。
- [ ] G02 多次載入／卸載後只有一個 Canvas、遊戲迴圈與音樂播放實例。
- [ ] 自動化除了檢查結束，也要涵蓋「可勝／可敗」與重新進入；預設一路亂按的腳本**不能替代**實際玩法品質驗證。
- [ ] 依每款遊戲設計建置獨立的固定種子（如適用）、動作序列與重播驗證，避免隨機結果讓 CI 不穩定。

**前次事實：** 本地 `python test_arcade.py` 的八種語系／尺寸測試通過；`node scripts/test-arcade-engines.cjs` 在 G05 未完成而失敗；局部資料夾執行 `verify-arcade` 因缺少既有頁面而遇到 ENOENT。兩者都不可被記為成功。

## D. Gate 2：六款各自玩法的嚴格驗收（全部 BLOCKER）

| 遊戲 | 必須通過的玩法條件 | 實際測試方式 |
|---|---|---|
| **G01 格鬥** | Burner 姐完整動作（移動、跳／落、三段連擊、受擊、閃避、專屬技能、KO）；三種敵人與二階段 Boss；視覺、命中框一致，第一關完整通關 | 以不同角色連續試玩、影片逐幀檢查命中與攻擊預告；確認不是靜態宣傳卡片平移 |
| **G02 防衛戰** | 七角色均可戰鬥、三波＋Boss、可逃離彈幕、技能可用；從新大廳進出不干擾原版 | 每英雄至少完整起手與結算；退出／重進 5 次；音訊、捲動鎖定及 RAF 清理 |
| **G03 下樓梯** | 平台隨機但可通關；可識別破裂、移動、陷阱；能死於危險、也能成功抵達深度 | 100 個 seeds 無必死地形；手機與桌機不同 FPS 測試 |
| **G04 彈珠** | 角度／力道影響彈道；碰撞與反彈穩定；三關不同挑戰；彈數限制勝負 | 固定物理更新、極高速碰撞、低幀率／旋轉螢幕測試 |
| **G05 排球** | 發球、過網、擊球、落地、得分，電腦 AI 有合理攻守，完整先得分終局 | 標準／專家各多場，無限來回與勝負閾值都測 |
| **G05 桌球** | 不把 Pong 冒稱真實桌球；若承諾「桌球」，需有球桌／球拍／反彈／發球與得分規則 | 與排球獨立的遊戲邏輯、按鍵說明與積分紀錄 |
| **G06 賽車** | 轉向、速度、煞車、氮氣、碰撞、檢查點、三圈與終局；賽道有曲率變化 | 慢速／高速、連續碰撞、跳過檢查點、計時與記錄測試 |

三種難度均需合理：不能只以敵人血量或高分閾值假裝難度差異。遊戲畫面、音效與角色辨識度必須經真人試玩，特別是 G01 的打擊感。

## E. Gate 3：跨裝置／雙語／音訊／效能（BLOCKER）

### 最低視窗矩陣

| 類別 | 測試尺寸／瀏覽器 | 核心驗收 |
|---|---|---|
| 桌面 | 1440×900 Chrome／Edge | 全螢幕布局、鍵盤、滑鼠、對話框、退出 |
| 中平板 | 768×1024 與橫向 | HUD、縮放、控制與觸控布局 |
| 手機小螢幕 | 375×812 Safari／Chrome | 不會水平溢出、戰場清楚、按鍵完整 |
| 手機較大 | 430×932 Safari／Chrome | 觸控點擊與捲動鎖定、方向變更 |
| 手機橫向 | 例如 844×390／932×430 | 操作區不遮住主角色／Boss、可正常退出 |
| 減少動畫／低階裝置 | `prefers-reduced-motion` + 30 FPS | 物理穩定、畫質可降級、無時間倍率問題 |

### 必須測試的動作序列

- [ ] 第一次從主站進入大廳 → 六張卡可見 → 點擊其中一款 → 選角 → 開始 → 暫停 → 繼續 → 過關／失敗 → 重試 → 返回大廳 → 問卷仍正常。
- [ ] 長按手機移動／攻擊且同時點閃避；放開或切 App 後按鍵狀態清除，不會角色持續移動。
- [ ] 遊戲前中後切換選曲；同一時間最多只播一首 OST；中途返回大廳沒有音效殘留；不需要使用者重整才能恢復。
- [ ] iOS Safari 第一次播放由使用者操作解鎖，失敗有可見錯誤，不阻擋遊戲；切出瀏覽器自動暫停。
- [ ] 重整後難度／音量／選曲／六款各自成績保存；清除 localStorage／隱私模式下不會報錯。
- [ ] 中日文所有遊戲入口、英雄名、勝敗對話框、說明、GA4 事件皆正確，無混雜語系與錯字。
- [ ] 遊戲返回後回復網站先前的卷軸位置及焦點；不留下 `body` 固定捲動 CSS。
- [ ] 無未處理 JS Error、白畫面、黑畫面、錯誤圖片、漏音樂、404 及任何阻塞型 P0 缺陷。

### 建議量測目標（工程目標，不是現在已達標）

- 桌面主動遊玩力求 60fps；低階手機以穩定 30fps 為底線。要採固定時間步長避免 FPS 改變物理／難度。
- 只在需要時載入對應遊戲與選定 OST，避免首次進大廳載入四至六首 MP3。
- 限制畫布 devicePixelRatio、粒子數及物件生成數量；同一工作階段連續玩 10 局後不能有不受控的記憶體增長。
- 遊戲卡圖片要有 alt 或被合理標示裝飾性；按鍵可以 Tab 與鍵盤觸達，重點字幕／對比清楚。
