# Bio-City Arcade v1.6 第 6A 批驗收報告

狀態：自動驗收通過但仍有可觀測性及覆蓋限制，PR #33 維持 Draft；未完成真機驗收。多人入口僅供私下驗收，未加入正式遊戲目錄。

## 實作與現有證據

共用大廳採手動交換邀請及回覆，沒有配對伺服器、STUN 或 TURN。兩條原生 RTCDataChannel 分別處理可靠控制訊息及無序、不重傳的輸入／畫面快照；G05 原有 120 Hz 物理與判分由房主執行，來賓呈現權威狀態。桌球和排球可以在同一連線切換；雙方準備及倒數後開始。進度不寫入單人遊戲紀錄。單人玩法與其他遊戲保留。

GitHub Actions run [40702857539](https://github.com/squallorc-dot/fun/actions/runs/40702857539) 的六項工作均通過（commit `25c28cd`）：包括兩個獨立 Chromium 程序的真實 WebRTC 桌球與排球完整對局及共用連線切換、原有六遊戲引擎、控制、低幀率、五章、中日文及畫面回歸。該次雙人測試確認移動和揮拍、同比分結算；它未要求雙方有效觸球，因此不能證明來回接球。

本地自動測試：G05 桌球 630 組、排球 144 發球／72 回球；新增雙人與快照 31 項、封包／生命週期與 10–240 FPS 一致性 67 項；Artifact 測試涵蓋 SHA-256 去重、逐位元還原、損毀、路徑穿越及失敗證據。瀏覽器未連線頁面曾檢查繁中／日文、桌面和手機橫直向；不代表真機對戰。

Commit `db82ea5` 新增延遲／掉包、實際引擎碰撞和長時間驗收程式。它透過兩個獨立瀏覽器、原生 RTC 和鍵盤輸入執行，從房主每個遊戲物理步觀察有效觸球和不同方連續回球，不設定球的位置、比分或勝負。矩陣在應用層呼叫 DataChannel.send 前兩端各注入目標 RTT 的一半，掉包只作用於不可靠的輸入／快照通道，可靠控制訊息不丟棄；這是可重現的應用層模擬，不是實際網路或系統封包整形。每個條件試玩 8 秒、交替測桌球和排球，不代表每個條件都完成兩種球賽。測試記錄 RTT p50/p95、jitter、FPS、輸入 ACK、畫面校正、丟包及有效觸球；輸入 ACK 不含畫面顯示延遲。長時間測試連續重開及切換，採集 heap、計時器、待處理資料數量並執行重新配對。合成 blur 只驗證失焦處理，並不等於實體手機切到背景。

新驗收 [GitHub Actions run 40733158532](https://github.com/squallorc-dot/fun/actions/runs/40733158532) 的六項工作全部通過（commit `db82ea5`）：20 個條件各通過 8 秒試玩；兩種球賽均觀察到雙方有效觸球及至少一次交替回球；超過 605 秒的重複完整對局、兩種球賽切換、重賽、合成失焦暫停及恢復、斷線與重新手動配對通過。不同條件下並未完整跑完每一種球賽，合成失焦不等於實際背景節流。結果 JSON 已打包為 `bio-city-friends-v16`，但目前雲端下載遭儲存端 403 拒絕，無法在此報告中核實各組 RTT、jitter、FPS、ACK、校正或確切觸球次數。程式採集 heap、計時器和待處理訊息數值，尚未證明記憶體或事件監聽沒有累積；真機網路品質與人體操作必須另行驗收。

## Artifact 與隱私

run 40733158532 GitHub 顯示的壓縮 Artifact：RC 畫面 212,367,225 bytes、G06 平衡 1,326,168 bytes、控制 4,205,405 bytes、多人 12,698,585 bytes、效能 8,595,052 bytes，合計 239,192,435 bytes（約 228.1 MiB）。這些是 GitHub 回報的實際壓縮大小，不能與本地原始檔去重節省量直接比較。程式保留全部來源路徑及 SHA-256，還原使用 `python3 scripts/package-qa.py --restore <下載的打包資料夾> --destination <新目錄>`；測試原檔和歷史 Artifact 不刪除。一般保存 7 天；失敗、main 或指定驗收保存 30 天，多人證據保存 30 天。本次從雲端下載舊多人 Artifact 時儲存端回傳 HTTP 403，無法在此環境確認該下載包內容；本地還原測試通過。

SDP／ICE 只放在交換欄位與連線記憶體；配對後清空欄位。勿將邀請或回覆貼到公開 issue、日誌或分析服務；房名是顯示名稱，不是自動搜尋短碼。瀏覽器可能拒絕產生 ICE host candidates；本 Cloud Chromium 受既有企業政策限制而無法產生，未變更該政策。

## 兩台真機同 LAN 操作

1. 在可信的測試環境從本分支提供靜態網站，以兩台裝置均信任的 HTTPS 網址開啟 `arcade/qa/friends-v16/index.html?lang=zh`（日文使用 `?lang=ja`）。`localhost` HTTP 不等於手機可用的安全來源。不要部署正式網站；請由有權限者提供臨時的私有 HTTPS 測試環境。
2. 兩台裝置連接同一 LAN，確認網路允許裝置互通；先設定音量與操作配置。選擇各自守護者，A 輸入房間名稱後按「建立邀請」。
3. A 以可信管道將完整邀請交給 B；B 貼上後按「讀取邀請並產生回覆」，再將完整回覆交給 A。A 貼上回覆並按「接收回覆」。只與可信對象交換，連線資料可能含網路位置。
4. A 選擇桌球或排球，雙方按準備，確認三秒倒數，兩人各自移動、有效擊球、來回接球直到正式結算；核對雙方比分。嘗試雙方暫停與同意恢復。
5. 返回好友大廳，確認仍為同一配對，再切換另一種球賽、完成對局及重賽；測試離開、斷線後重新配對，確認不殘留上一局輸入與比分。
6. 於繁中／日文、手機橫直向及四種配置測試實際按鍵與安全區；以 Windows 瀏覽器重做。分別測試音樂、音效、切換背景與恢復；記錄裝置、作業系統、瀏覽器及結果，但不記錄 SDP 或 ICE。
