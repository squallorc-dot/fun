# 第 6A 批：Windows 與兩台手機同 LAN 人工驗收

狀態：**全部待人工**。此流程不部署正式網站、不開放公網；由驗收者在可信的私人 Wi-Fi 上自行操作。三台裝置均須可以直接互通，訪客網路的用戶端隔離可能阻擋連線。只把邀請／回覆交給可信對象，內容包含網路位置，不要放到公開 issue、網址或分析系統。

## 在 Windows 建立私有 HTTPS 測試頁

1. 在 Windows 安裝 Git、Python 3 和可信來源取得的 `mkcert`。在私人目錄取得 PR #33 的分支；確認 `git rev-parse HEAD` 對應要驗收的 PR head。檢查 Windows 的 Wi-Fi IPv4，例如 `192.168.1.23`；以下以 `<LAN_IP>` 代表實際位址。
2. 由驗收者在 Windows 執行 `mkcert -install` 以建立並信任本機測試 CA，再以 `mkcert -cert-file "$env:TEMP\bio-city-local-cert.pem" -key-file "$env:TEMP\bio-city-local-key.pem" <LAN_IP> localhost 127.0.0.1` 建立該 IP 的證書。證書與私鑰必須放在網站根目錄之外，私鑰與測試 CA 私鑰只留在 Windows，切勿分享或提交；只複製 `mkcert -CAROOT` 目錄中的 `rootCA.pem` 公開 CA 證書給測試手機。
3. 在兩台手機依作業系統的官方方法安裝並明確信任該臨時 CA：iOS 安裝描述檔後還需在「憑證信任設定」啟用完整信任；Android 的設定路徑與應用是否接受使用者 CA 依版本而異。只在自行管理且信任的測試設備執行，結束後刪除該 CA 信任。瀏覽器必須顯示連線可信；不要使用略過憑證警告的方式當作可信 HTTPS。
4. 在倉庫根目錄建立不含 `.git` 的暫存測試副本，然後從該副本啟動僅供 LAN 的一次性 Python HTTPS 靜態伺服器（Python 3.8+）：

   ```powershell
   $qaDir = Join-Path $env:TEMP ("bio-city-qa-" + [guid]::NewGuid().ToString())
   New-Item -ItemType Directory $qaDir | Out-Null
   git archive HEAD | tar -x -C $qaDir
   Set-Location $qaDir
   python -c "import http.server,ssl,sys; s=http.server.ThreadingHTTPServer(('0.0.0.0',8443),http.server.SimpleHTTPRequestHandler); c=ssl.SSLContext(ssl.PROTOCOL_TLS_SERVER); c.load_cert_chain(sys.argv[1],sys.argv[2]); s.socket=c.wrap_socket(s.socket,server_side=True); s.serve_forever()" "$env:TEMP\bio-city-local-cert.pem" "$env:TEMP\bio-city-local-key.pem"
   ```

   請僅允許私人網路中的測試設備連接 TCP 8443；若 Windows 防火牆需要調整，由驗收者自行允許私人網路並於結束後撤銷。不要設定路由器轉發或上傳憑證。使用全新空的暫存目錄，避免夾帶其他私有檔案；測試後按 Ctrl+C 停止伺服器並移除暫存副本、測試私鑰與臨時 CA 信任。
5. 在兩台手機分別開啟 `https://<LAN_IP>:8443/arcade/qa/friends-v16/index.html?lang=zh`；日文改為 `lang=ja`。若其中一台顯示不可信、WebRTC 不可用或連不上，記錄設備／瀏覽器及錯誤，停止該項並排查，不要假裝測試成功。

## 兩台不同手機

- **配對**：A 設房名並選英雄、建立邀請；以可信管道交給 B。B 選英雄、貼上邀請並產生回覆；A 貼上回覆。確認兩邊房名、角色、準備狀態。房名只是顯示名稱，無自動尋房。
- **桌球及排球**：兩人分別準備，確認倒數。實際雙方移動、揮拍／跳躍、合法觸球和交替回球，各完成整場；核對雙方比分、勝方、只結算一次。返回大廳後在同一配對切換另一球類、重賽，確認上一局輸入與比分已清空。
- **操作與畫面**：分別測直向、橫向、左手、右手、雙手與桌面配置，檢查按鍵、安全區、可視空間、英雄和完整動畫；測繁中與日文。在多人遊戲開啟操作設定，確認暫停與恢復。
- **音訊**：由使用者手勢啟用音樂，測四首 OST、音量、音效、暫停與恢復；留意 iOS／Android 音訊政策或靜音開關。記錄實際聽到的結果。
- **背景及中斷**：兩人遊戲中由一台切換其他 App 或鎖屏，檢查暫停、無卡鍵與雙方同意恢復；關閉一方網頁或暫時斷開 Wi-Fi，確認未完成對局作廢，重開後重新交換邀請、再遊玩。不得假設瀏覽器一定維持背景連線。
- **Windows**：用 Windows 瀏覽器作其中一方，重複配對、鍵盤／桌面配置、兩球種、暫停、失焦及重配。記錄作業系統、瀏覽器版本、手機型號、方向、每次結果與延遲數據，勿記錄 SDP／ICE。

失敗、不可用或未執行的項目逐項記錄；不同作業系統信任臨時 CA 的相容性與網路隔離均需在現場判斷。
