- GA4 的既有自訂維度：`hero_name`、`hero_used`、`ost_name`、`recommended_hero`。遊戲名稱、難度、章節、模式與勝敗尚待視需求註冊事件範圍自訂維度。

## GTM-5M4KVKNX 待執行設定（需要有 GTM 發布權限）
建議先建立 GA4 Event tag，事件名稱由 Data Layer Event Name 帶入，以下分別建立 Custom Event triggers，避免將一般頁面操作當成遊戲：
- `arcade_game_start`
- `arcade_game_finish`
- `arcade_campaign_stage`
- `arcade_game_exit`
- `arcade_ost_select`
- `ost_persistent_track`（全站連續 OST 選曲）
- `site_navigation_click`（選用，避免大規模不必要事件）

事件資料層變數建議：`game_id`、`chapter`、`mode`、`difficulty`、`hero_id`、`hero_used`、`outcome`、`final_score`、`language`、`track_id`。請注意有些是非預設 GA4 參數，需要適當設定自訂維度；且不要重複觸發原本 `game_completed` 或 `play_ost_audio` 的既有標籤。

## 人工放行步驟
1. 在 GTM Preview 對應網站測試新遊戲開始／通關／退出、章節及 OST 切換，確認標籤只各發送一次。
2. 在 GA4 DebugView 確認事件名稱與參數均成功抵達。不能以 API 歷史報表的舊事件取代。
3. 對照日文與繁中及 G05 排球／桌球雙模式；確認事件不包含個資。
4. 發布 GTM 版本、保存版本編號、再次實測；經過資料處理延遲後以 GA4 Data API 查證。

## v1.1 連續 OST 焦點修正
- 原先只有單一布林 `otherAudio`，兩個音源播放交錯時一個暫停可能提前恢復背景 OST。
- 已改為 Set 追蹤同時播放的音訊物件，網頁切換時清除前頁已消失的引用。
- 遊戲 OST 只在實際播放成功後登記為占用焦點；失敗解除焦點。
- 用繁／日文 Playwright 模擬雙音源交錯、遊戲進出時的焦點狀態；自動化不能取代 iPhone／Android 實體播放檢查。
