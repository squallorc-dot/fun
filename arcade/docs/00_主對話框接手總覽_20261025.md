## 4. 不變更的產品決策

- **六款全部完成、與大廳和 OST 一起正式上線**，不能先公開 G01–G05 或單獨切正式導覽。
- G05 包含兩個真正可玩的運動模式：「排球」與「桌球」，必須獨立測試、獨立判定勝負。現有 Pong 式體驗不能冒充真實桌球物理。
- 原版射擊遊戲、8 題情境決策分析、正式角色圖片、既有音樂及兩種語言不得丟失。
- 每一款至少：開始、清楚操作、難度、玩家掌控、可觀察回饋、勝利、失敗、結算、重新挑戰、返回大廳；不可只呈現展示畫面。
- 手機可操作，無長網頁捲動干擾；專用遊戲視窗必須正確處理直／橫向及退出後捲動與焦點。
- 音樂不自動偷播；必須由使用者手勢解鎖，音樂與 SFX 不互相控制，切到背景不繼續播。
- 專案使用現有 GTM `GTM-5M4KVKNX`；正式展示站 GA4 既有 ID `534706548`，不與 BV 購物網混用。
- GitHub Pages 現行對外網址 `https://squallorc-dot.github.io/fun/`；**開發分支不等於正式可公開預覽網址**。要先建立受控測試環境才邀請試玩。

## 5. 主對話框第一個執行批次：以阻塞和驗證為先

1. 讀取目前 `main` 與開發分支最新提交；完整 checkout，執行四組 Node 與瀏覽器測試，輸出可回溯測試報告。
2. 優先處理 **BLOCK-01 G05 無法結算**、**BLOCK-02 G02 新大廳整合**、**BLOCK-03 `verify-arcade` 所檢查的正式入口尚未整合**、**BLOCK-04 真機 OST／音訊焦點與授權**。
3. 整合共用 GameShell／AudioManager／SaveManager，而不是單純讓六個引擎各自常駐。請避免事件監聽器、RAF、音樂播放器、PointerCapture 在退場後洩漏。
4. 完善 G01 打擊感與人物動畫，並逐項完成 G03–G06 的動作公平性與作品內容深度。
5. 完成一次全套 Release Gates，產生測試證據、變更清單、授權清單、回退記錄，經使用者對六款完整體驗確認後才合併 `main`。

## 6. 開發分支工作流程

1. 工作前從遠端讀 `development/bio-city-arcade-six-games` 最新 commit，避免沿用先前記錄的 SHA。
2. 一次解決一個能驗收的任務，使用清楚的 commit，附測試結果與已知問題。
3. 不中途把開發版程式推回 `main`，不改正式網站對外導覽；可以用獨立測試預覽驗收，不應把 dev 分支當作公網已發布。
4. 有任何 blocker，記錄重現步驟、環境、預期／實際、修復與回歸測試；不能只說「已修正」。
5. 發布採原子合併與回退方案。**一次上線代表一起公開六款，不代表必須把所有變動塞成一個 Git commit。**
