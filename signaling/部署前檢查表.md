# v1.6.1 Cloudflare 訊號服務：部署前檢查表

本文件是準備事項；目前沒有部署或取得雲端驗收。此 Draft PR 不可直接發布，實體 Windows／Android／iPhone 及服務驗收均未完成。

## 使用者需要完成的安全授權

1. 確認欲使用的 Cloudflare 帳戶與網域由使用者控制，且 SQLite-backed Durable Objects、WebSocket Hibernation、Workers 及該帳戶的免費額度實際可用；檢查當前用量、限制、超額行為及預算警報。若需付費方案或政策變更，停止並另行取得授權。
2. 由使用者以 Cloudflare 官方授權方式，在隔離終端安全登入或提供最小權限憑證；不要把 Token 貼入聊天、儲存庫、PR、測試記錄或網址。需要 Workers 部署及 Durable Objects 對應資源權限；實際最小權限依帳戶政策核對。
3. 另行明確核准受限的 Workers 測試部署（如適用）與正式服務綁定；兩者都不代表 GitHub Pages 上線授權。使用者最終確認後才能合併或發布。

## 工程檢查

- 固定候選 PR HEAD，確認該 SHA 的六項 CI、真正 RTC 和完整遊戲回歸通過；不得用其他 SHA 的綠燈代替。檢查最新待辦與測試失敗紀錄。
- 確認只接受實際 GitHub Pages HTTPS origin；驗證外部請求經 Cloudflare 可信 ingress 注入 `CF-Connecting-IP`。測試代理可偽造該標頭，不代表雲端驗證。檢查反向代理或 Worker 子請求不會讓客戶端自填的值被信任。
- 設定高熵且唯一的 `RATE_SECRET`，使用 Cloudflare secret 管理而非 `wrangler.toml`、前端、日誌或 Git。只在使用者授權的終端操作，例如 `openssl rand -hex 32 | npx wrangler secret put RATE_SECRET`；勿使用 CI 的本機測試字串。不得啟用新的付費服務。
- 審閱 `ROOMS`／`RATE_GATES` 綁定及 `v1`／`v2` SQLite migration 的實際帳戶支援、成本及回復影響。觀察兩人房間、來源速率限制、共用 NAT、公平使用、到期 alarm、WebSocket hibernation／恢復及高流量濫用處理。
- 驗證同源 HTTPS、CORS、WebSocket、CSP 與瀏覽器政策；不得啟用未授權 STUN／TURN 或外部信令。無 STUN／TURN 不保證跨網路連線。
- 排查伺服器、代理、錯誤與追蹤系統：不得記錄 SDP、ICE、邀請憑證、IP 或把邀請資料寫入 GA4、Analytics、網址查詢或持久存儲。邀請 fragment 僅提供給使用者主動選擇的可信分享對象。
- 真實測試兩個獨立裝置的建立／邀請／QR／房間碼核准、雙向 RTC、兩方選角、重賽、切遊戲、信令中斷、RTC 中斷、房間過期、資源清理和一致結算。Windows Chrome／Edge、Windows＋Android、Windows＋iPhone、iPhone＋Android 同 Wi-Fi 均須留下真人證據。未測項目保持「待人工」。
- 只有服務與測試完成後，才在授權的候選版本設定實際訊號 HTTPS 端點及正式入口；核對中日文、快取、OST、單人存檔、所有六項 CI 與正式 GitHub Pages 工作流程。

## 回復與事故處置

記錄已驗證上一版 main Commit `14518b80b5af0bd265d63ca954d0c866909cc0ff`、當時 Pages 的來源（main 根目錄）、Worker 部署版本、綁定與密鑰狀態。發現問題時停止新配對並依已授權操作回退 Pages／Worker；不得在事前假定回退會保留現有 RTC 或 Durable Object 資料。現有一局 RTC 與信令獨立；若 RTC 中斷，不可自行宣稱原局已恢復或重複結算。發生憑證暴露時使用 Cloudflare 機制輪替密鑰並撤銷受影響邀請，依據實際事件記錄影響範圍。
